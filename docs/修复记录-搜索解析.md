# 修复记录：部分歌曲"搜不到"（富士山下 / 不要说话）

日期：2026-10-11　严重度：高（导致搜索整体失效）　状态：**已修复并验证**

---

## 现象

搜索 `富士山下`、`不要说话` 返回**空结果**（`每日晴天`、`七里香` 等却正常）。

## 根因（典型但隐蔽）

酷我搜索接口返回的其实是**非法 JSON** —— 某些字段的值里带**未转义的双引号**：

```json
{"AARTIST":"Eason Chan",
 "ALBUM":"What"s Going On...? (Remastered 2019)",     ← 这里的 " 没转义
 "ALBUMID":"9570","ARTIST":"陈奕迅", ...}
```

而旧代码做的是：

```python
txt = body.decode(...).replace("'", '"')   # 粗暴替换
data = json.loads(txt)                     # ← 直接抛异常
except Exception: return []                # ← 静默返回空 → 表现为"搜不到"
```

所以：**歌一直在（HIT=3455），是被解析器丢掉了**；且异常被吞掉，UI 只能看到"无结果"。

## 修复（`kuwo_pc_download.py::search`）

1. **先试严格 JSON**；成功则**按文档顺序保序**遍历（原实现用栈，会把顺序倒过来，
   导致原曲排到后面、专辑曲目跑到前面）；
2. 失败则**容错扫描**：
   * 定位 `"abslist"` → 用花括号配平把数组切成一条条 item；
   * 每条用正则取值（`"SONGNAME":"..."` 等），**不受其它字段里的脏引号影响**；
3. 额外收益：兼容 App 式响应里嵌套的 `content[].interestpage.abslist`；
4. 取值后统一 `html.unescape()`（修掉 `&nbsp;`、`&amp;`）。

## 注意

* 修复在**共享模块** `kuwo_pc_download.py` 里，GUI 与 TUI 都会生效；
* **已经打开的 TUI / GUI 需要重启**才会加载新代码（Python 已把旧模块载入内存）；
* 排查手法值得记：**别吞异常**。这次若把 `json.loads` 的异常打印出来，一眼就能看到
