# 接口速查与维护手册（能用多久 / 坏了怎么修）

> 结论先说：**"算法和接口不变 → 就能一直用"这个前提不成立**，而且本项目**已经踩到过两次**
> 接口侧的变动（搜索返回脏 JSON 导致"搜不到"、歌词接口 HTTPS 被限流而 HTTP 可用）。
> 所以正确的心态不是"会不会坏"，而是**"坏了多快能修"**。
> 本文把所有对外依赖列成一张表，并标注失效时的修复位置，把修复成本压到最低。

---

## 一、寿命评估：谁先坏

按**失效概率从高到低**排列（都是我观察到的真实风险点）：

| 环节 | 依赖什么 | 失效概率 | 失效后果 | 修复难度 |
| --- | --- | --- | --- | --- |
| **播放地址解析** `convert_url2` | 服务端"客户端自报即放行"的行为 | 🔴 **最高** | 下载/试听全废（最致命） | 中～高：需要重新抓包对齐参数 |
| **歌词**（H5 接口） | 公开 H5 接口 + 限流策略 | 🔴 高（**已发生**） | 歌词页空白 | 低：已有四级降级 + 可加音源 |
| **搜索** `search.kuwo.cn/r.s` | 旧客户端 `ver=kwplayer_ar_9.2.2.1` 参数 | 🟠 中高 | 搜不到歌 | 低：换 URL/字段解析 |
| **CDN 直链** | `*.kuwo.cn` 域名与签名参数 | 🟠 中 | 下载失败 | 低：改 UA/Range/域名 |
| **q 加密算法** | 客户端 `ylzsxkwm` 密钥与自定义 DES 表 | 🟡 中（**服务端升级即废**） | 解析类请求全废 | 高：需重新逆向（数小时～数天） |
| **封面地址拼接** | `img1.kuwo.cn/star/albumcover/...` | 🟢 低 | 只是没图 | 极低 |
| **本地功能**（播放器/歌词动画/曲库/队列） | 无外部依赖 | ⚪ 不会坏 | —— | —— |

**关键认知**：最脆弱的一环不是加密算法，而是**播放地址解析**——它依赖的是服务方"懒得校验"的行为，
一旦补上校验（或改为强制登录/签名），整条下载链路会当天失效。加密算法反而相对稳定（换密钥成本高，服务方通常几年才动一次）。

## 二、全部对外依赖速查表

| # | 用途 | 请求 | 我们发什么 | 期望响应 | 代码位置 |
| --- | --- | --- | --- | --- | --- |
| 1 | 搜索 | `http://search.kuwo.cn/r.s?all=<kw>&pn=&rn=&ft=music&client=kt&ver=kwplayer_ar_9.2.2.1&vipver=1&show_copyright_off=1&rformat=json&encoding=utf8&mobi=1` | 关键词 | `{"abslist":[{SONGNAME, ARTIST, MUSICRID, DURATION, web_albumpic_short, MINFO, PAY}]}` | `kuwo_pc_download.search()` |
| 2 | 播放地址 | `http://mobi.kuwo.cn/mobi.s?f=kuwo&q=<加密串>` | `type=convert_url2&sig=0&format=flac&br=2000kflac&rid=<rid>` | `TP=content` + 明文 URL | `resolve_url()` |
| 2b | 同上（回退） | 同上 | `format=mp3&br=320kmp3` / `128kmp3` | 同上 | `resolve_url()` |
| 3 | 歌词 | `http://m.kuwo.cn/newh5/singles/songinfoandlrc?musicId=<rid>` | （**必须 http**，https 被限流） | `{"data":{"lrclist":[...]}}` | `fetch_lyric()` 第 1 级 |
| 3b | 歌词（App 通道） | `mobi.s?f=kuwo&q=...` + `type=lyric&lrcx=1` | 加密串 | `TP=content lrcx=1` + zlib 内容（**当前返回加密载荷，校验不过会自动跳过**） | `fetch_lyric()` 第 2/3 级 |
| 3c | 歌词（兜底） | `music.163.com/api/search/get` → `/api/song/lyric` | 歌名+歌手 | JSON `lrc.lyric` | `_netease_lyric()` |
| 4 | 封面 | `https://img1.kuwo.cn/star/albumcover/500/<短路径>` | `web_albumpic_short` 去掉首段 | 图片 | `kuwo_app.cover_url()` |
| 5 | 音质/体积 | 搜索结果内 `MINFO` 字段 | —— | `level:ff,bitrate:2000,format:flac,size:26.62Mb;...` | `search()` 内解析 |
| 6 | FLAC 标签 | 本地文件内嵌 Vorbis comment | —— | `title/artist` 用于规范命名 | `flac_tags()` |

**关键常量**（改这些就能应对大部分小变动，全在 `kuwo_pc_download.py` 顶部）：

```python
UA_OK  = "okhttp/3.10.0"                       # 老接口认这个 UA
UA_WEB = "Mozilla/5.0 ... Chrome/122.0 ..."    # 网页/图片接口
CRED_MIN = ("user=0&corp=kuwo&source=kwplayer_ar_5.1.0.0_B_jiakong_vh.apk&p2p=1")
H5_HDR  = {"User-Agent": UA_MOBILE, "Referer": "https://m.kuwo.cn/"}
```

## 三、出问题时的 3 步流程（5 分钟定位）

```powershell
# 第 1 步：跑自检，看哪一环 ❌
python tools\healthcheck.py

# 第 2 步：抓原始响应（不要只看解析后的结果）
python tools\search_probe.py 富士山下     # 搜索接口六种参数组合对比
python tools\lyric_probe.py               # 歌词九个备选端点对比

# 第 3 步：按第 1 步给出的"修复方向"改对应函数，再跑 tools\app_test.py 回归
python tools\app_test.py                  # 搜索/试听/下载/歌词 四项端到端
```

### 常见症状 → 处置

| 症状 | 大概率原因 | 处置 |
| --- | --- | --- |
| 搜索返回 0 条 | 接口字段改名 / 脏 JSON / 被限流 | 跑 `search_probe.py` 看原响应；若是新字段名，改 `search()` 的 `_field()` 取值 |
| "拿不到播放地址" | `convert_url2` 行为变了 | 先试其它音质分支；再抓包对齐参数模板 |
| 歌词空白 | 接口限流 | 已自动降级到网易云；仍失败则再补一家音源到 `_netease_lyric` 旁 |
| 下载到 0 字节 / 403 | CDN 校验 UA 或 Range | 改 `download()` 的请求头；试去掉 Range 分段 |
| 全部解析类请求失败 | q 算法/密钥变了 | 用手机抓包（见下）比对 `q` 结构，必要时重新逆向 |
| 界面乱码/不显示 | 与接口无关 | 见 `docs/UI检查与优化报告.md` |

## 四、让寿命更长的工程措施（已落地的部分）

| 措施 | 现状 |
| --- | --- |
| **多级降级** | 歌词 4 级（http H5 → https H5 → App 通道 → 网易云）；播放地址 3 级音质回退 |
| **本地缓存** | 歌词落盘（`%LOCALAPPDATA%\MusicBoxStudio\lyrics`），接口挂了也能显示已听过的歌词 |
| **引擎与界面解耦** | 换音源只需改 `kuwo_pc_download.py`，`kuwo_app.py`/`ui_kit.py` 完全不用动（换整个音源也行） |
| **一键自检** | `tools/healthcheck.py`（7 项）+ `自检.bat` 双击即可 |
| **探针工具** | `tools/search_probe.py`、`lyric_probe.py`：多端点/多请求头横向对比，替代盲猜 |
| **回归测试** | `tools/app_test.py`：改完跑一遍就知道有没有改坏 |
| **接口文档化** | 就是本文——每条依赖都对应到函数，避免"只有原作者知道怎么改" |
| **优雅降级** | 音源全挂时，**本地曲库/播放器/歌词动画仍然完全可用**（不依赖任何接口） |

## 五、如果哪天彻底失效了

1. **先跑自检**：通常只有 1~2 个环节坏了，其余照常；
2. **看第 2 节的速查表**：每一项都有明确的代码位置；
3. **抓包对齐**（最后手段）：手机端 `adb reverse` + `settings put global http_proxy` 抓一次真实请求，
   比对参数差异（本项目早期就是这么确定 q 参数结构的，方法与注意事项见 `docs/技术报告-*.md`）；
4. **换音源**：引擎层是隔离的，理论上可以整体替换为其它平台（本地功能与界面完全复用）。

---

## 六、一句话总结

> 这不是"算法正确就能永久运行"的离线工具，而是**在线服务的非官方客户端**。
> 它的寿命 = 服务方保持现状的时间；我们能做的是**让它坏得可定位、修得够快、并且核心本地功能永不失效**。
> 当前状态：**7 项自检全部通过**（见 `tools/healthcheck.py` 输出）。
