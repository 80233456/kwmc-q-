## 一、本轮三个硬成果

### 成果 1：修掉了一个真实的模拟器 bug（关键）
之前 `relocate()` 把**库内自己定义的符号**也当成外部依赖打了桩 —— 导致原厂 kpk 里
`md5x`（本库导出的 `_Z4md5xPKcji`）根本没执行真身，后面全是垃圾值，所以一直崩。
修正策略：**dynsym 里有定义（shndx≠0）的符号 → 指向镜像里的真实实现**；
只有真正未定义的才建桩。修好后原厂 kpk 才真正跑起来。

### 成果 2：抓到原厂 kpk 真正 MD5 的完整输入（386 字节）
在 `md5x`（`0x7b1cca3284`）设 hook，记录它被调用的参数：

```
[md5x] len=386  mode=0xa9e3e905  sret=0x723feca0
输入全文(386 字节):
  $Aivn&2@BZ*A$qsv                          ← 16 字节随机盐（每次不同）
  type=convert_url_with_sign&br=320kmp3&format=mp3&sig=0&rid=228908&priority=1
  &user=<device_id>&android_id=<device_id>&prod=kwplayer_ar_12.2.2.4
  &corp=kuwo&newver=3&vipver=12.2.2.4&source=kwradio_ar_6.0.0.9_B_jiakong_vh.apk
  &p2p=1&q36=<q36>&approval=false
  &loginUid=<loginUid>&loginSid=<loginSid>&appuid=<appuid>
  &kpk=&kwso=kwplayer_ar
-> md5 = 0ce60b99697237edeeaf110c0d8321cb
```

**这是完整的明文模板**（已存 `work/vendor_md5_input.bin`）。关键细节：
* 密文里带 **16 字节随机盐**（所以需要随密文一起传给服务端才能被验证）；
* 参数里有一个 **`&kpk=`（空值占位）** —— 极可能就是放签名/校验的位置；
* 尾部被缓冲区（386 字节）截断。

### 成果 3：确认了可用的**服务端判定器**
| 请求 | 结果 |
| --- | --- |
| 垃圾 q / 空 q | **HTTP 404**（空体） |
| 我们抓包拿到的真 q | **HTTP 200** + 加密体（`TP=content ...`） |

→ 可以在纯 PC 上**闭环搜索**加密方案，无需手机。

## 二、本轮排除的方案（可复现）

按"签名 + 固定密钥 AES"结构，用服务端判定器试了 **760+ 个组合**：

* 签名位置 4 种（替换 `&kpk=` / 追加尾 / 前置 / 盐+签名+参数）
* 固定密钥 62 个候选（`md5/sha256` 派生、ASCII 截断，种子取自镜像里所有已知串）
* 分组模式 2 种（AES-ECB、AES-CBC-iv0）
* 编码 3 种（base64 / hex / 盐hex+base64）

**全部 404** → 结论：AES 密钥**不是可猜的字符串派生**，而是镜像里的**硬编码二进制块**
（这也符合壳的做法）。脚本：`test_q_schemes2.py`。

## 三、当前唯一缺口

原厂 kpk 在 md5 之后走**libc++ 运行时**（`std::string` / `stringstream` / `locale`），
我们的桩支撑不住，崩在 `0x7b1ceb87ec`（对空指针虚调用）。
也就是说：算法主体已明（盐 + 参数 → MD5），但**"密钥 + 分组模式 + 输出编码"这一步没跑完**。

### 下一步（三条，按性价比）

**A2-a-1｜静态找密钥常量（推荐，最快）**
明文模板与调用顺序都已确定，直接反汇编 kpk 在 `md5x` 之后的那段
（`0x7b1cc6e6f0` - `0x7b1cc6efxx`）：
* 找出它把哪些地址传给分组密码初始化（密钥必然来自某处 `adrp+add` 或 `mov/movk` 立即数序列）；
* 把该 16/32 字节 blob 抠出来当 AES 密钥，配合已知结构打判定器验证。

**A2-a-2｜补 libc++ 运行时**
实现（或 hook）`std::string` / `basic_stringstream` / `locale` 的最小语义，
让 kpk 跑到结束 → 直接拿到**真实 q** → 与判定器交叉验证。

**A2-a-3｜批量二进制密钥爆破**
从镜像中提取 kpk 代码引用过的所有数据块（`adrp+add` 目标），
把其中 16/32 字节的块全部当 AES 密钥打判定器（数量可控，判定器闭环）。
